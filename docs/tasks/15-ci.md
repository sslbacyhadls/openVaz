# 15. CI: тесты и сборка под aarch64

- Приоритет: P3
- Размер: S
- Кто: Александр
- Зависит от: 01
- Статус: заблокирована

## Зачем

Проверки сейчас запускаются только руками. Когда в проекте двое, ошибку в чужом PR дешевле
поймать автоматически.

## Что сделать

GitHub Actions на каждый PR и пуш в `master`:

1. `cargo fmt --check`
2. `cargo clippy --no-default-features --all-targets -- -D warnings`
3. `cargo test --no-default-features`
4. `cargo build --release --target aarch64-unknown-linux-musl --no-default-features`

Образ QEMU в CI не собирать: долго, нужен `unshare`.

## Готово, когда

PR с намеренно сломанным тестом показывает красную проверку, исправленный показывает зелёную.

## Решения

- Workflow на pull_request и push в master: fmt, строгий Clippy без оконных зависимостей,
  тесты и release-сборка aarch64 musl. QEMU-образ не собирается.
- Для чисто Rust-зависимостей достаточно rust-lld, поставляемого с Rust: сторонний
  кросс-компилятор и отдельный образ контейнера не добавляются.
- `src/link.rs` не меняется по прямому указанию пользователя. В нём есть старое
  несоответствие rustfmt, поэтому у объявления модуля в `src/lib.rs` установлен
  `#[rustfmt::skip]`. Этот файл не проверяется rustfmt до отдельной правки владельцев
  контракта; компиляция, Clippy и тесты проверяют его как обычно.
- Разрешённое исключение для эмулятора: только writeln вместо write с переводом строки,
  enumerate вместо индексации DAMPERS и стандартное форматирование, отдельные коммиты.

## Почему не сделано

- GitHub принял workflow и создал прогон [43097082584](https://github.com/sslbacyhadls/openVaz/actions/runs/43097082584),
  но он несколько минут остаётся в `queued`, список jobs пуст, логов runner нет.
  `gh run watch --exit-status` ожидает результат; `gh run view`, API jobs/check-suites
  подтверждают очередь. API approvals и pending_deployments возвращают пустые списки.
- Создан временный намеренно падающий тест: локально он красный; на GitHub результат
  не получен из-за очереди. Тест удалён перед следующим пушем, рабочая ветка проходит проверки.
- Прогон после исправления будет запущен повторным push. Пока нет выполненного CI,
  условие «красный тест → зелёный тест» и зелёная aarch64-сборка в GitHub не подтверждены.
  Локальная aarch64-сборка успешна. По правилу пользователя работа продолжается задачей 13;
  если очередь заработает, статус и результаты будут обновлены.

## Что сделано

- `.github/workflows/ci.yml`: pull_request и push в master; fmt, Clippy с `-D warnings`,
  тесты и сборка release aarch64 musl через поставляемый с Rust rust-lld; без QEMU.
- `src/model.rs`: derive Default вместо ручной реализации, инициализация тестового
  состояния одним выражением, assert вместо сравнения с true.
- `src/paint.rs`: координаты текста объединены в пару, убрано предупреждение о числе аргументов.
- `src/lib.rs`: локальное исключение rustfmt только для неизменённого `src/link.rs`.
- `src/fb.rs`, `src/layout.rs`, `src/model.rs`, `src/paint.rs`, `src/window.rs`: rustfmt,
  отдельный коммит форматирования панели.
- `src/bin/car.rs`: только writeln и enumerate, отдельный lint-коммит;
  `src/bin/car.rs`, `src/vehicle.rs`: только rustfmt отдельным коммитом.
  `src/link.rs` и `emu/car.sh` не изменены.
- Этот файл и `docs/tasks/README.md`: решения, результат и блокировка внешнего CI.
- `cargo fmt --check`: exit 0, вывода нет.
- `cargo clippy --no-default-features --all-targets -- -D warnings`: exit 0, предупреждений нет.
- `cargo test --no-default-features`: 16 passed, 0 failed.
- `cargo build --release --target aarch64-unknown-linux-musl --no-default-features`
  с linker=rust-lld на отдельном Rust stable 1.99.1: exit 0; file подтверждает
  статический ELF aarch64. Toolchain и target установлены в /tmp, системный Rust не менялся.
