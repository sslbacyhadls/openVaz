# 06. Запуск панели на Orange Pi

- Приоритет: P1
- Размер: M
- Кто: Влад (плата)
- Статус: в работе

## Зачем

QEMU даёт обычную ARM-машину с virtio-gpu и virtio-tablet. На плате будет HDMI-контроллер H616,
USB-сенсор через хаб и другой набор устройств ввода. Пока программа не запущена на настоящей
плате с настоящим экраном, неизвестно, работают ли `src/fb.rs` (framebuffer, разрешение) и ввод
через evdev с реальным сенсором.

## Что сделать

1. Сверить плату по надписи: Orange Pi Zero 2, H616, 512 МБ. Записать сюда.
2. Поставить Armbian для этой платы на отдельную карту (это отладочная система, не итоговый
   образ).
3. Собрать `cargo build --release --target aarch64-unknown-linux-musl --no-default-features`,
   скопировать `openvaz` на плату.
4. Подключить экран 1024×600 по HDMI и сенсор через хаб вместе с ELM327.
5. Запустить `openvaz --fb /dev/fb0`. Проверить разрешение, касания по кнопкам, свайп.
6. Снять потребление памяти (`ps -o rss`) и загрузку процессора при перетаскивании ползунка.

## Ход работы

Отладочная система, не итоговый образ карты: Armbian Bookworm minimal для Orange Pi Zero 2,
`Armbian_25.5.1_Orangepizero2_bookworm_current_6.12.23_minimal.img.xz`. Это не Zero 2W.
Надпись на плате сверяется до записи карты: H616 и 512 МБ.

Сборка панели на компьютере разработчика. Системный `ld` не понимает флаг
`--fix-cortex-a53-843419`, поэтому линкер этой цели — `rust-lld` из `.cargo/config.toml`.
В `PATH` должен быть каталог `rustlib/x86_64-unknown-linux-gnu/bin` из sysroot rustc.

    cargo build --release --target aarch64-unknown-linux-musl --no-default-features --offline

Команда проходит: получается статическая программа aarch64
`target/aarch64-unknown-linux-musl/release/openvaz`. На плату она ещё не копировалась.

На плате, после копирования `target/aarch64-unknown-linux-musl/release/openvaz`:

    ./openvaz --fb /dev/fb0

Пока панель на экране и палец двигает ползунок, `emu/board-report.sh` печатает модель, ядро,
размер framebuffer, USB, устройства ввода и RSS. Вывод вставляется в таблицу ниже.

На компьютере, с которого задача взята в работу, платы нет: в локальной сети виден только
маршрутизатор, framebuffer и USB-адаптера ЭБУ нет. Таблица поэтому пустая.

## Готово, когда

- Записано: модель платы, версия Armbian и ядра, что показал `fbset` или `/sys/class/graphics/fb0`.
- Панель на экране, касания попадают туда же, куда в QEMU.
- Сенсор и ELM327 одновременно видны через хаб (`lsusb`, `/dev/input/event*`, `/dev/ttyUSB0`).
- Записаны RSS и загрузка процессора.
