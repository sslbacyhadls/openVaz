# 08. Слой выходов: PCA9685, GPIO, ШИМ

- Приоритет: P2
- Размер: L
- Кто:
- Зависит от: 06, 07
- Статус: открыта

## Зачем

Сейчас каждое действие на экране превращается в строку `выход N значение X` (`Session::publish`),
которая уходит в журнал и в текстовый порт эмулятора. На плате те же события должны двигать
настоящие сервы, вентилятор и реле.

## Что сделать

1. Одно место, куда уходят `OutputEvent`: два варианта, текстовый порт (как сейчас, для QEMU) и
   железо. Выбор по аргументу или переменной окружения.
2. Железо:
   - PCA9685 по `/dev/i2c-N`: частота 50 Гц, каналы 0-4;
   - пин 11 (OE) через `/dev/gpiochipN`: импульсы разрешаются только после того, как заданы
     стартовые положения;
   - пин 7 (запрос кондиционера) через `/dev/gpiochipN`;
   - пин 8 (ШИМ вентилятора): аппаратный ШИМ H616 через `/sys/class/pwm`, если он выведен на
     этот пин, иначе выбрать другой пин и поправить [module.md](../module.md).
3. Калибровка в профиле Калины: для каждой заслонки ширина импульса в крайних положениях и
   инверсия (из задачи 07). Простой текстовый файл, как `settings`.
4. Без новых зависимостей, если хватает `libc` и ioctl: проект уже так работает с framebuffer.

## Готово, когда

- На столе (плата, PCA9685, одна серва, светодиод вместо реле): кнопки на экране двигают серву
  в крайние положения из калибровки, кондиционер зажигает светодиод.
- После `kill -9` программы светодиод гаснет, импульсы на сервах пропадают (подтяжки из
  [module.md](../module.md)).
- В QEMU всё работает как раньше, через текстовый порт.
